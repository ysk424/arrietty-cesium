# 操作方法

Windows / UE 5.8 向けの海・湖で漕ぐゲームです。Arrietty-row の負荷連動の
推進力、操舵、ケルビン波、白波、短い Tracker ロストの補助を引き継いでいます。
SteamVR を OpenXR ランタイムに指定し、
HMD・バー中央のTracker・心拍計を起動します。ローイングマシンは漕いで
起こしてください。スマートフォンのアプリが接続中なら切断します。

PowerShellでこのリポジトリを開き、`./row.ps1 "Koh Hong"` を実行します。
機器を使わないデモは `./row.ps1 "Koh Hong" -Demo` です。

大きな景色を進む場合は `./row.ps1 "Koh Hong" -mag 5` のように移動を拡大できます。
`-mag` / `-Magnification`は1～10、標準1、小数対応です。Pythonからは`--mag` / `--magnification`です。
艇の計算速度が10km/hなら5倍で地形上を約50km/hで進みます。速度計は倍率後の
`WORLD km/h x5`を、距離計は倍率後の移動距離を表示します。
漕ぐ力・校正・旋回角速度・水面の高さ・波と音の強さは従来通りです。
旋回半径は倍率に応じて広がります。航行範囲は標準半径3kmのままなので、
必要なら`-RadiusKm`（1～10）も指定します。倍率後の進路の岸・島・範囲境界で停止します。

- **テンキーEnter**：開始前の校正へ進みます。下の3段階で自動的に開始します。
- 運動中の **テンキーEnter**：一時停止。再開時も校正します。
- **テンキー0**：記録を保存して停止し、湖上の出発位置へ戻ります。
  Num Lockがオフの場合のInsertと、Escでも停止できます。
- 体を左／右に移動すると左／右へ操舵します。
- 運動中の短いTrackerロストは、頭の前後移動による補助または惰性で待ち、
  復帰すると自動的に通常へ戻ります。HMDロストや長いロストで停止した場合は、
  復旧後にEnterで再開します。

開始・再開の手順：

1. `1/3 GET READY`：Enterから2秒間、キーから手を戻して普段の姿勢になります。
2. `2/3 HOLD STILL`：マシンの正面を向き、体を中心にして1秒間静止します。
   この間のHMD位置を平均して中心を決めます。姿勢が動くと1秒を数え直します。
3. `3/3 ROW THE BAR 0 / 2`：左右に体を傾けず、バーをまっすぐ前後に2往復します。
   40cm以上の十分なストロークで行います。軸を取得すると自動的に運動が始まります。

校正中は艇が動かず、仮想の距離・運動時間・ストローク数にも加算しません。
校正中にEnterを押し直しても校正は中断しません。やり直す場合はテンキー0で停止し、
Enterから再開します。校正前・校正中の案内はHMDから見やすい位置に表示し、
完了後は艇上の計器位置へ戻ります。表示は `1/3` → `2/3` → `3/3` と進みます。
40秒以内に校正できなかった場合はタイムアウトして待機します。追跡が失われた場合も
自動的に進み出さず、機器と姿勢を確認してEnterからやり直します。

左右の方向はバーの往復から求め、顔の角度で左右軸を決めません。中央から
**左右±8cmは直進範囲**です。範囲を超えると穏やかに曲がり始め、20cmで最大になります。
高速域では船速に合わせて旋回速度が増え、等倍の最大舵で半径約10mを目標に曲がります。
18cmの横移動なら半径約14.4mが目安です。傾け始めや加速中は平滑化の影響があります。
計器の緑の帯が直進範囲、動く目印が現在の左右位置です。`CENTER` は直進、
`LEFT` / `RIGHT` はその方向への操舵を示します。数値は中心からの左右位置（cm）です。
表示と操舵には同じ平滑化した位置を使い、緑の帯へ戻ると曲がり残りを止めます。
漕いでいる間は中心や軸を自動で動かしません。詳細は [STEERING.md](STEERING.md)。

通常のキーボードのEnterでも操作できます。長押しは1回の操作として扱います。
キー操作の対象はゲームウィンドウです。反応がない場合はPC側でゲーム画面を
クリックしてから押してください。`Enter received / check HMD + bar` はキーを
受け取ったものの追跡条件を満たしていない状態です。正面を向き、HMDとTrackerの
追跡を確認してから再度テンキーEnterを押します。

距離・速度は仮想の艇が実際に進んだ値です。時間は一時停止を除く開始後の
経過時間です。心拍数が未受信、接触不良、または5秒以上更新されない場合は
`--` と表示します。本体の出力が受信できない場合は、Trackerから推定する
モードであることを表示します。

計器の小さい行に `BT 80 W | LOAD 6 | GAME 480 W` のように、本体のW・
ダイヤルの負荷・ゲーム用の補正Wを表示します。**補正W = 基準W × 負荷レベル**
で推進力を計算します。基準Wは本体の受信Wを優先し、未受信または3秒以上
古いときはバー速度からの推定値（`Tracker est`）です。負荷は受信するたびに
反映するので、運動中のダイヤル変更にも追従します。最大負荷は16で、11～16も同じ計算です。負荷が未受信、1～16の
範囲外、または3秒以上古い場合は `LOAD -- (x1)` と表示して倍率1を使います。
補正Wはゲーム用の調整値で、身体の実測出力ではありません。基準Wの上限は
BTで1000 W、Tracker推定で240 Wです。船には従来の水抵抗・加速上限・速度上限
が働くので、負荷を6倍にしても速度がそのまま6倍になるわけではありません。
ハンドルを止めると推進は止まり、艇は惰性で進みます。負荷は本体のダイヤルで
変更し、アプリから本体を操作しません。
本体が新しい0 Wを送っている間は、負荷が11～16でも補正Wは0です。
本体の0 Wを未受信とみなして推定出力に置き換えることはありません。
移動倍率`-mag`は、この補正Wの計算を変えず、最後の移動量に掛けます。

記録先は `apps/row/unreal/ArriettyCesium/Saved/Sessions/` のCSVです。艇の距離・時間・速度・
心拍数に加えて、本体が報告する距離・時間・速度・出力も別の列に保存します。
左右位置、操舵量、旋回速度も保存し、偏りを後から確認できます。
`power_w` は本体の元のWです。`resistance_level` に受信負荷、`power_multiplier`
に実際の倍率、`game_power_w` に補正Wを記録します。不明な負荷・Wは空欄です。
`speed_kmh`は倍率前の計算速度、`movement_magnification`は移動倍率、
`world_speed_kmh`と`distance_m`は倍率後の地形上の速度・距離です。
`resistance_raw`は検証前の受信負荷、`resistance_age_s`は受信からの秒数です。
無効・古い値も診断用に残しますが、負荷補正には使いません。未受信なら両方空欄です。
補正Wは推進力に使う出力の値であり、校正中・一時停止中に受信しても艇や運動時間
は進みません。待機・一時停止中も、新しい本体Wと負荷は画面に表示します。
本体の列は本体側の累積値です。テンキー0は本体のカウンターをリセットしません。
デモの記録は `source=demo` で区別します。個人の機器IDと運動記録は公開しません。

## 短いTrackerロストの補助

通常どおり校正して漕ぎ始めると、Trackerが見えている間に頭とバーの前後移動の
関係を学びます。運動中にバーが体の影へ入った場合、HMDが正常なら最大1.25秒
待ちます。関係を学べていて直前までバーが動いていた場合は `ROWING / HMD ASSIST`
と表示し、頭の前後移動でバーの動きを短時間推定します。学習不足の場合は
`BAR LOST / COASTING` と表示して、推進せず惰性で待ちます。

Trackerが戻ると `BAR RETURNING / COASTING` になり、0.15秒連続して安定した後に
通常の漕ぎへ戻ります。この間はEnter操作が不要です。長いロスト、HMDロスト、
大きな位置飛び、100msを超えるフレーム停止では従来どおり停止します。
校正中には補助を使わないため、開始前の2往復にはTrackerの追跡が必要です。

頭と腕は完全には同じ動きをしないため、補助中の推進は推定です。補助中・復帰確認中は
新しいストロークを数えず、余分な入水音も出しません。復帰後に実際の戻し動作を
確認してから数え直すため、表示のストローク数が少なくなることがあります。
左右操舵は実際の頭の横移動を使い、±8cmの直進範囲と中心位置を維持します。

通常起動でも切り替えと停止理由をログに残します。セッションCSVの `bar_source`
は `tracker / hmd_assist / coast / reacquiring`、`bar_gap_s` は検出したロストからの
経過時間、`tracking_issue` は運動中の停止理由です。校正失敗はUEログの
`ROW_CALIBRATION_FAILED` にフレーム時間と追跡状態を記録します。高頻度の姿勢記録は
行いません。実際の見え隠れでの補助効果や Cesium を使った実機の動作は、
このフォークでは未検証です。

`./row.ps1 "Koh Hong"` で通常起動すると、動作ログ `logs/row/training.log` を毎回上書きします。
このファイルの世代バックアップは作りません。距離・時間などのトレーニング履歴CSVは
`apps/row/unreal/ArriettyCesium/Saved/Sessions/` に運動ごとに保存します。過去に検証用として
保存したログ・姿勢記録・画像も別に保管します。動作ログの不具合を調べる場合は、
次回起動で上書きされる前に確認してください。

`./tools/probe.ps1 -Seconds 60` でC++の受信を確認できます。別の受信テストや
ローイングアプリと同時に実行せず、表示を確認しながら20～30秒漕いでください。
初回は `./tools/build_native.ps1 -Devices` で受信テストをビルドします。

開発時の準備は `./tools/prepare.ps1`。Cesium プラグインを取得し、ボートと水面の
素材・マップを生成します。現在の検証範囲は
[VALIDATION.md](VALIDATION.md) を参照してください。

## 効果音と音量

入水・引く音は漕ぎ動作、水切り音は船速に連動します。待機・校正・一時停止中は
静かな水面と風だけが鳴ります。左は右より6 dB大きくしてあります。
通常起動で有効です。音量を下げる場合は `./row.ps1 "Koh Hong" -Volume 0.5`、
消音は `-Volume 0` を使います（範囲0〜1、初期値0.8）。
素材や音のつなぎ方は [効果音の説明](AUDIO.ja.md) を参照してください。
