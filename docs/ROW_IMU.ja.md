# WT9011DCLでバーの引きを検出する

RowはTracker 3.0に加え、バーへ固定したWT9011DCLのBLE 5.0通知を入力にできます。
このモードではバーのTrackerは不要です。HMDの追跡は引き続き必要です。
バーの中央へ縦に近い向きで固定した実機から、約10 Hzの通知を受信して確認しました。
テープが緩んだり、取り付け位置が変わった場合は再校正してください。

## 起動と校正

1. センサーのボタンで電源を入れ、SteamVRとHMDを準備します。
2. いつもどおり `./row.ps1 "Koh Hong"` などで起動し、場所を確認してYを入力します。
3. 地形準備後、Enterを押します。バーを前へ出し、機器の正面を向きます。
4. 2秒の準備の後、頭とバーを1秒静止させます。
5. **前へ出したバーを最初に手前へ引き、前へ戻す動作を2往復**行います。校正後、自動で開始します。

IMUの座標はSteamVRの部屋の座標と直接対応しません。そのため、このモードでは
静止する1秒間の正面視線で操舵の基準方向を決めます。正面を向いて校正してください。
開始後は基準方向を固定し、頭の左右移動で操舵します。首を振るだけでは曲がりません。
8 cmの直進域、Enterの開始・一時停止・再開、校正中のEnterの扱い、テンキー0の
中止・記録・開始位置への復帰は維持します。Trackerモードの軌跡による軸校正も維持します。

表示は `ROWING / WIT IMU`、BT出力がない場合の推定出力は `IMU est` です。
記録の `bar_source` は `imu_velocity` となります。これは加速度からの推定速度で、
Trackerによる絶対位置の測定ではありません。

## 接続設定

`config/row.local.json` に既存のrower・心拍設定を残して、以下を設定します。
今回使用した実機はローカル設定済みです。機器のアドレスはGitへ入れません。

```json
{
  "bar_input": "wt9011dcl",
  "imu_address": "機器のBLEアドレスをローカルで設定",
  "imu_address_type": "random"
}
```

アドレス種別は広告で実測した `random` または `public` を保存します。
広告が見つからない場合も、確認済みの種別で再接続を試みます。
別の機器を自動選択したり、Trackerへ自動で切り替えたりはしません。
Trackerへ戻す場合は `bar_input` を `tracker` にします。元の `tracker_serial` は残しています。
Windowsの「ペアリング済み」は通知の受信中という意味ではありません。
今回確認した接続はBLEで、COMポートは使いません。

## 判定と停止

加速度・角速度・角度を含む20バイトの `55 61` 通知だけを使用します。
センサー姿勢で加速度を回転し、静止時に測った重力・定常偏差を除きます。
校正の往復から水平の運動軸と最初の引きの符号を求め、短時間の速度を推定します。
速度の減衰時定数は4秒で、静止判定が0.35秒続くと推定速度をゼロにします。
各通知は一度だけ積分します。BLEの10 HzとUEの描画頻度は独立です。
引き・戻しの閾値と推進・抵抗計算には既存のRowモデルを使用します。

通知が0.25秒以上途絶えた場合、HMD追跡喪失、異常なフレーム間隔、異常な
センサー値では停止します。IMUの通信断にHMDによるバー補助は使いません。
再接続だけでは再開せず、Enterで校正し直します。
ローイング機器・センサーへの設定コマンドは送りません。BLE通知の購読だけを行います。
負荷、機器の出力値、水面、音、Flyの制御は変更しません。

## ローカル診断

ゲームや別のセンサーアプリを閉じた状態で実施します。

```powershell
./apps/row/tools/build_native.ps1 -Devices
./apps/row/tools/probe.ps1 -ImuOnly -Seconds 30
```

この診断ではHMD、ローイング機器、心拍計を開きません。
Pythonで生データを保存する場合の任意の追加環境:

```powershell
./apps/row/.venv/Scripts/python.exe -m pip install -r apps/row/tools/requirements-diagnostics.txt
./apps/row/.venv/Scripts/python.exe apps/row/tools/wit_probe.py --seconds 180
```

未登録環境では単一のWT901候補を発見して有効な通知を受信した後、`--select` で
アドレスと種別を保存できます。入力モードは別途 `bar_input` で明示します。
ログ・生データ・機器IDは無視対象の `logs/row/wit-*/` に保存します。
実行中の記録ディレクトリに `stop.local` を作ると終了します。

## 検証範囲

2026-09-12、モレーン湖の地形補正とOpenVR読み込み先の修正後、ユーザーから動作OKの確認を得ました。
通常起動のログでもOpenVR読み込み、地形準備、校正から開始まで進んだことを確認しています。
これは初回の実機起動・校正・開始の確認で、長時間の検出精度評価ではありません。

実機の通知受信、記録した10往復のC++再生で10回検出、同じ記録の
最初の2往復によるオンライン校正と残り8回の検出を確認しました。
この記録を開発にも使用しており、独立した精度評価ではありません。
静止・姿勢だけの変化・通信断・重複通知・HMD操舵は合成入力で確認しています。
低速・短い引き、強い手首の回転、取り付けのずれ、長時間のドリフト、
推進感覚と音のタイミングは引き続き詳しい実走確認が必要です。
機器受信・記録再生やネイティブテストをVRでの受け入れ確認とは扱いません。

通信形式とUUIDは[WITMOTION公式SDKの仕様例](https://github.com/WITMOTION/WitBluetooth_BWT901BLE5_0/blob/main/Python/BWT901BLE5.0_python_sdk/device_model.py)
および[製品資料](https://witmotion-sensor.com/products/wt9011dcl-bluetooth5-0-compact-size-accelerometer-inclinometer-sensor)を確認し、独立実装しています。
