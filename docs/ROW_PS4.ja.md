# PS4コントローラで漕ぐ・旋回する

バーに固定したPS4互換コントローラの加速度とジャイロから、漕ぐ動きを推定します。
HMDはUEのOpenXRから取得します。Quest 3はMeta Quest Link / Air LinkとMeta OpenXR、
VIVEはSteamVR OpenXRを使用してください。どちらのHMDでも同じPS4操作です。
PS4モードではHMDの左右移動・顔の向きで旋回しません。

## 操作

| ボタン | 動作 |
|---|---|
| □ | 開始・一時停止・再開（Enter相当） |
| △ | 校正中止・終了・記録・開始位置へ戻る（テンキー0相当） |
| L1 / R1 | 押している間、左 / 右へ通常旋回 |
| L2 / R2 | 押している間、左 / 右へ強く旋回 |

□の長押しで開始・停止を繰り返しません。校正中の□は校正を取り消しません。
同時押しは△を優先します。○・×には開始停止を割り当てません。
通常旋回は従来の最大操舵量の半分、強い旋回は最大です。同じ側では強い方が優先し、
左右を同時に押すと直進します。離すと旋回入力は直ちに0になります。停船中は旋回しません。
キーボードのEnter・テンキー0も従来どおり使用できます。

## 接続と設定

まずWindowsにBluetooth接続します。互換品のセンサー対応は機種ごとに確認が必要です。
対応するPS4 Bluetooth拡張レポートを使います。Xbox入力への変換ソフトは不要です。
USB接続、別形式の互換品、単純なボタンだけのレポートはこの実装の対象外です。

```powershell
./apps/row/.venv/Scripts/python.exe -m pip install -r apps/row/tools/requirements-diagnostics.txt
./apps/row/.venv/Scripts/python.exe apps/row/tools/ps4_probe.py --select --seconds 10
```

`--select`は接続中の候補が1台の場合だけ、センサー受信後に`config/row.local.json`の
`bar_input`を`ps4`にし、`ps4_hid_path`へ機器を保存します。既存のrower・心拍設定は維持し、
変更前設定を`logs/row/ps4-settings-before.local.json`へ保管します。識別子はGitや端末へ出しません。
ペアリングし直してパスが変わった場合も再度選択してください。別の機器を自動選択しません。

診断のみは`--select`を省略します。ゲーム実行時にはPython/hidapiを使わず、
C++のWindows HIDワーカーが読み出します。拡張レポートを有効にする通信だけを送信し、
振動・ライト・スピーカーの効果を指定しません。ローイング機器の負荷は引き続き読み取りのみです。

## 取り付けと開始

バーを動かしてもずれない位置に固定し、L1/R1/L2/R2と□・△を押せる状態にします。
傾けた取り付けにも対応し、角度は固定値を設定せず、実際の静止姿勢から推定します。
正面を向いてバーを前へ出し、通常の`row.ps1`で場所をY確認して地形の準備を待ちます。
□で2秒の準備、1秒の静止、手前への引きから2往復を行うと開始します。
校正後の□休止からは、□でその場から再開できます。

ジャイロで姿勢を推定して加速度を回転し、静止時の重力を除きます。
残留偏差を除くフィルターと減衰する速度推定で引き・戻しを区別し、既存の漕ぎモデルへ渡します。
これは絶対位置・正確な移動距離の測定ではありません。機械から受信する出力・負荷の補正、
水面・音・航行範囲・移動倍率の計算は維持します。

## 通信復帰

PS4の有効な入力が0.25秒以上途絶えた場合、移動と漕ぎの音を止めます。
**走行中のPS4通信断からは、有効なセンサーとHMD追跡が戻ると自動復帰します。**
位置・距離・経過時間・校正を保持し、通信が抜けた区間の速度を積算しません。
再接続時に□を押す必要はありません。□で意図的に休止した場合や△で終了した場合は
自動復帰しません。校正中の通信断は校正のやり直しが必要です。
HMDだけの追跡喪失や地形・岸の停止は、PS4の再接続で自動解除しません。
切断中のバーの向きの変化、長時間の姿勢ドリフト、強い手首の回転は実走確認が必要です。

## 検証範囲

提供された実機からBluetoothの加速度・ジャイロ各3軸を受信し、取り付け後の□・△・
L1/R1/L2/R2を確認しました。37.71秒の記録は7,517件でCRCエラーなしでした。
記録再生ではオンライン校正から漕ぎ検出へ進みます。ただし10往復を依頼した記録から
全区間11回（校正後9回）を検出しており、最後の移動を含めた回数の一致は未確認です。
この記録を開発にも使用しており、独立した検出精度評価ではありません。
合成入力では2往復の校正後に残り8回を検出し、静止後の推進停止を検証します。
自動テスト・生データ受信はRowの実機VR受け入れ確認を意味しません。

通信形式の参照: [SDLのPS4 HIDドライバー](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_ps4.c)。
